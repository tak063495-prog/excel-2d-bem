# issue #1のレビューと修正（2026-10-09）

対象は[issue #1](https://github.com/tak063495-prog/excel-2d-bem/issues/1)です。修正前のmain `3510d4cc5c0ba56e45d98837e5a2f75f18c60601`の組込VBAをWindows版Excelで実行し、本文の面積判定と追加候補の自己DE積分の両方を再現しました。指摘を妥当と判断して修正しています。

## 修正前の再現

1 m四方の2D RECT、原点X=Y=1E8 m、各辺4分割、二次要素を使用しました。原点／モデル寸法の比1E8は入力ガードが許可する範囲です。

| 状態 | Excel内の結果 |
|---|---|
| 元コード・原点(0,0) | メッシュ生成成功、32幾何節点／16境界要素 |
| 元コード・原点(1E8,1E8) | 「反時計回りの閉輪郭が必要です」で拒否 |
| 面積だけを相対座標へ変更 | メッシュ生成成功 |
| 面積だけを変更して解析 | 「基本解の評価点が一致しています。特異積分が必要です」で停止 |

原点が大きいと、絶対座標の積から面積を求める際に大きな数同士の差が生じ、小さい面積が失われます。また自己DE積分はパラメータ上では評価点と離れていても、絶対座標への写像で同じDouble値に丸められ、基本解の二点距離が0となりました。

検証中には、`100000000 + 1/96`が旧JNumで`100000000.010417`となり、約15桁のテキスト化で座標精度を失うことも確認しました。[修正前の実測記録](../issue1_reproduction.json)を保存しています。

## 実装変更

- `ValidateTopology`は領域原点を引いた座標の符号付き面積を補償加算します。面積の判定は丸め誤差の尺度を考慮し、時計回り・退化輪郭を引き続き拒否します。
- `PolygonArea`は元から先頭頂点を基準にしていました。この関数には補償加算を追加しています。
- 求解用の要素・コロケーション・自己積分・内部場・FMMは領域ごとの同じ局所座標を使います。幾何の写像・微分も先頭節点との差で計算します。
- 異なる局所原点の領域を接合する場合は、原点差を含めて場節点を対応付けます。
- 境界結果、CSV、NPZのコロケーション位置へ原点を戻します。入力メッシュと内部評価点の絶対座標を維持します。
- JNumは短い表記で往復が一致する場合はその表記を使い、それ以外ではIEEE754の仮数からDecimalで最大17有効桁の表記を組み立てます。JSON/CSV/VTKを同じ形式へ統一します。Windows APIはビット列のコピーにだけ使い、数値計算はVBAです。

DEのパラメータ距離カットオフ`1E−12`、基本解の零距離チェックは変更していません。形状の向きや退化の検査を省略する対応ではありません。

## 実行時エラー13

局所座標化の検証中、従来の方法で`New CSolveRegion`を作成する内部場の検証ルーチンでは、FrameOriginがEmptyのまま`EvaluatePoint`へ渡されました。`point(i−1) − sr.FrameOrigin(i−1)`の配列参照で型不一致が発生し、ユーザーから報告された黄色の行と一致しました。

`CSolveRegion.Class_Initialize`でFrameOriginを3成分のゼロ配列へ初期化しました。通常の求解時は領域原点へ置き換え、従来の絶対座標で作る呼出しにはゼロ原点を使用します。コンストラクタの検査に加え、従来の内部場ルーチンで2D RECT/CIRCLE、3D BOX/SPHEREの境界近傍計算を再実行しています。

## 修正後の検証

[`verify_issue1.py`](https://github.com/tak063495-prog/excel-2d-bem/blob/main/verify_issue1.py)は配布ブックを読取専用で開き、実際の組込VBAを実行します。

- 大座標RECTのdense定数／二次、DEレベル0・3・4、遠方相互作用を持つFMM二次を原点付近と比較。
- 検証したRECTの演算作用ベクトルは平行移動前後で一致（最大差0）。FMM 384未知数の相対残差は約4.42E−11。
- 自己積分点を全て走査し、零距離0件。各辺16分割の二次要素で最小距離は約4.60E−14 m。絶対座標のDouble間隔より小さい距離を局所座標で保持。
- 2D/3Dの異材接合、3D定数／二次BOXの平行移動を比較。
- JSON/CSV/NPZ/VTKの座標と、CSV結果取込を確認。VTKの要素ごとの複製節点も照合。
- 3,009数値をテキスト往復し、PythonとVBA Valで同じDouble値を確認。小数点がカンマの環境も確認。最小の非正規化数はExcelが0へ丸める場合があるため、COMで実際に受け取った値を比較。
- 大座標POLYGONの両入力方向、細長い非退化多角形、時計回りの実メッシュ拒否、零寸法の拒否を確認。

別途、既存のFMM 28項目、演算選択・出力29項目、境界近傍・入出力11項目、状態・接合など23項目を再実行しました。FMM比較は元Pythonの作用ベクトル・境界解・内部場を参照し、2D 1536未知数と3D二次1224未知数を含みます。autoは実測時間を使うため、混合演算の検証では並行実行の負荷で選択が変わるケースを確認し、負荷が落ちた状態でdense/FMM併用を再確認しました。

最新の数値と件数は[追加検証](../issue1_regression.json)と[全体検証](../検証結果.json)を参照してください。確認したケースの合格を示す記録であり、任意形状・全設定の無誤差を保証するものではありません。[大座標の限界](limitations.md#大座標と数値精度)も明記しています。
